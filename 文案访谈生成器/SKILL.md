## 描述

根据个人定位文档和一个选题，选择最匹配的内容结构与个人展示问题，并将它们整合、改写成一条从开头到结尾的文案问题链。

## 使用目标

帮助用户把定位文档中已经沉淀的内容结构、分析问题和个人展示方式，快速转化为适配某个具体选题的创作提纲。用户只需要依次回答问题，就能逐步补齐一篇内容所需的信息。

## 输入内容

用户需要提供：

1. 一份个人定位文档，文档中应包含可用于内容创作的结构、问题或编排方式。
2. 一个需要创作的选题。

如果输入不足以识别定位文档或选题，应先询问缺失信息，再继续执行。

## 执行流程

### 一、读取个人定位文档

完整读取用户提供的定位文档，从中识别以下内容：

- 文档中包含哪些可供选择的内容结构。
- 每个内容结构适合分析什么类型的问题。
- 每个内容结构包含哪些核心分析问题。
- 每个内容结构是否提供了默认编排路线、展开顺序或内容节奏。
- 文档中有哪些用于呈现个人经历、判断过程、专业能力、差异化、证据、结果或服务边界的问题。

以文档中的实际内容为准，不补写定位文档中不存在的结构。

### 二、理解本次选题

分析选题想要讨论的核心内容，包括：

- 选题中的主要对象与核心议题。
- 观众最需要被回答的问题。
- 选题中的关键场景、矛盾、变化或决策。
- 这篇内容最终希望帮助观众理解、判断或解决什么。
- 适合支撑这篇内容的事实、经历、案例或证据类型。
- 这篇选题中的解决方案，能怎样和内容结构整合。

这一阶段只用于匹配和改写问题，不直接替用户生成答案。

### 三、选择最匹配的内容结构

比较定位文档中的所有候选结构，判断哪个结构最能解释本次选题，并选择一个最匹配的主结构。

选择时重点判断：

- 结构所处理的问题是否与选题的核心议题一致。
- 结构中的问题能否推动选题逐层深入。
- 结构的默认编排路线是否适合这篇内容的表达过程。
- 用户回答完这些问题后，是否能够形成一篇逻辑完整的内容。

### 四、筛选个人展示问题

从定位文档的个人展示相关内容中，选择最适合本次选题的问题。优先选择能够自然完成以下作用的问题：

- 交代判断或观点从何而来。
- 展示分析、追问、拆解或决策过程。
- 呈现真实经历、个人视角或差异化能力。
- 补充结果、变化、反馈或其他可信证据。
- 说明方法的适用范围、现实条件或服务边界。

个人展示问题应服务于正文逻辑，并插入最需要建立理解或信任的位置，不单独堆放成自我介绍。

### 五、把通用问题改写为选题专属问题

保留原问题在内容结构中的分析功能，再根据本次选题进行具体化改写。

改写后的问题应当：

- 明确正在询问的对象、场景或事件。
- 对准选题中真正需要展开的矛盾、变化、原因、代价或选择。
- 能够让用户通过回忆事实和表达判断直接作答。
- 每个问题只承担一个主要任务。
- 使用自然、清晰、适合口头思考的语言。

不要直接照搬定位文档中的通用问法。问题经过改写后，应当让人仅阅读问题本身，就能感受到它是为当前选题设计的。

### 六、整合成从开头到结尾的问题链

以所选内容结构的内在逻辑和默认编排路线为主线，将改写后的结构问题与个人展示问题合并、排序。

整合后应做到：

- 第一组问题能够帮助用户找到合适的内容入口。
- 后续问题逐步补充场景、事实、矛盾和判断。
- 中段能够完成对核心问题的深入分析。
- 个人展示问题出现在与正文关系最紧密的位置。
- 后段能够形成方法、选择、行动、边界或结论。
- 每回答一个问题，都会为下一部分提供新的信息。
- 相邻问题不重复询问同一件事。

问题数量根据选题和结构的实际需要决定，以能够完整推动一篇内容为准。

## 输出格式

除非用户另有要求，最终只输出一张两列表格，不补充结构分析、选择理由或写作建议。

| 问题                     | 回答 |
| ------------------------ | ---- |
| 适配当前选题的第一个问题 |      |
| 适配当前选题的第二个问题 |      |

输出时必须保持：

- 第一列只放按照文案顺序排列的问题。
- 第二列保持空白，留给用户填写。
- 不替用户虚构经历、观点、案例或答案。
- 不增加第三列。
- 不把内容结构问题和个人展示问题拆成两张表。

## 输出前检查

在输出前检查：

1. 是否读取了定位文档中的全部候选内容结构。
2. 是否选择了与当前选题最匹配的结构。
3. 是否筛选了真正适合这篇内容的个人展示问题。
4. 是否已将通用问题改写为选题专属问题。
5. 是否形成了从开头到结尾能够连续作答的问题链。
6. 是否删除了重复、抽象、无法直接回答的问题。
7. 是否只输出了“问题／回答”两列，且回答列保持空白。
